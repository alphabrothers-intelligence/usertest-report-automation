# 레이아웃 렌더러 실측 갭 목록 (Phase 12b)

PRD 2.2.2절 5단계(레이아웃 렌더)에 들어가기 전에, **레이아웃 카탈로그 40종이 지금 실제로
어떻게 그려지는지**를 렌더로 확인한 결과다. "기존 블록을 그대로 쓰면 된다"는 앞선 판단이
어디까지 맞고 어디서 틀리는지를 코드가 아니라 그림으로 확정하는 것이 목적이다.

**측정 방법**: 웹 작업공간(`/viewer` 데모, 리바랩스 정량)을 헤드리스 Chrome으로 PDF 출력(41쪽)
→ 원본 발행 보고서(`data/[알파브라더스] 리바랩스_..._0904_상연.pdf`, 56쪽)의 같은 장과 대조.
레이아웃 코드·조건은 `docs/NOTION_STAGE_MAPPING.xlsx`, 시각 기준은
`docs/사용성테스트 결과 보고서 레이아웃 v.0.5.pdf`.

**측정일**: 2026-08-25. 데모에는 정성 분석 결과가 없어 정성 블록(L11 계열)은 "대기" 상태로
렌더된다 — 구조는 확인 가능하나 내용 대조는 정성 분석이 있는 보고서로 다시 봐야 한다.

## 2. 코드 단위가 아닌 구조 문제 (더 중요)

개별 레이아웃보다 이쪽이 원본과의 거리가 크다.

### 2-1. ~~Ⅲ장 "문항 요약 페이지"라는 골격이 없다~~ → 골격은 있었다. 정성에 묶여 있던 것이 문제 (해결)

원본 8쪽은 문항 하나가 **2×2 표 한 장**으로 완결된다.

```
Q6. "펫과의 산책" 기능의 만족도는 몇 점입니까?        ← L10b
┌─────────────────────────┬───────────────┐
│ 만족도 점수 평균 : 6.35 / 10   │ 표준편차 : 2.54  │   ← L9
├─────────────────────────┼───────────────┤
│ 만족도 분포도 (L1b)          │ 주요 키워드 도출 (L12) │
├─────────────────────────┼───────────────┤
│ 주관식 응답 감정 분석 (L8 반원도넛) │ 응답 요약 (L11a)   │
│ 긍정·부정·중립 % 표 (L8t)      │ [긍정 의견 요약] …   │
└─────────────────────────┴───────────────┘
```

**정정(2026-08-25)**: 이 골격은 `featureQualitativeBlocks()`에 원본 그대로 이미 구현돼 있었다.
데모 화면에서 안 보였던 진짜 이유는 **정성 결과가 없는 문항을 통째로 건너뛰었기 때문**이다
(`if (q.categories.length === 0) continue`). 원본 페이지의 상단 절반(평균·표준편차 배너,
만족도 분포도, 키워드 칸)은 raw data만으로 그려지는 정량 블록인데, 정성 분석 전이거나 한 문항이
실패하면 그 쪽이 통째로 사라져 보고서 구조 자체가 달라졌다.

**해결**: 순회 기준을 정성 문항 → **정량 기능**으로 뒤집었다. 페이지의 주인은 정량이고 정성은
있으면 얹는다. 정성이 없는 문항은 하단 절반만 "정성 분석 승인 후 표시"로 남는다.
정성 분석 실패가 정량 결과 출력까지 막지 않는다는 원칙(PRD 11장 15번)과 같은 방향이다.
렌더 확인: 기능 6개 문항 페이지가 모두 생성되고 Q번호·평균·표준편차가 원본과 일치한다.

### 2-2. ~~장 안의 순서가 원본과 반대다~~ → 오진이었다

**정정(2026-08-25)**: `buildFeatureSection()`은 문항별 페이지를 먼저, 종합 차트·순위표를
나중에 낸다 — 원본·레이아웃 PDF와 같은 순서다. 데모에서 문항별 페이지가 대기 문구 한 줄로
축약돼 있어 종합 차트가 먼저 오는 것처럼 보였을 뿐이다. 2-1을 고치면서 함께 해소됐다.

### 2-3. 쪽이 비어 있다

블록 하나만 든 A4 쪽이 여러 장 나온다(예: 작은 "정성 분석 대기" 박스 하나로 한 쪽). PRD
3.3.3절(A4 쪽 편집 웹뷰)에서 다룰 문제지만, **레이아웃을 원본과 같게 만들어도 쪽 채우기가
안 되면 "원본과 같은 보고서"가 되지 않는다** — 두 작업은 같이 가야 한다.

### 2-4. 화면 UI가 인쇄물에 섞인다

"PNG 다운로드", "AI 분석 재생성", "클릭하면 바로 내용을 수정할 수 있습니다" 같은 편집용
컨트롤이 출력 PDF에 그대로 찍힌다. `data-copy-ignore`는 복사에만 적용되고 인쇄에는 적용되지
않는다.

### 원본과 대조하는 방법 (이 루프를 그대로 쓸 것)

코드 리뷰로는 이 종류의 차이를 못 잡는다. **반드시 렌더해서 원본과 나란히 본다.**

```bash
# 1) 웹 작업공간을 통째로 PDF로 출력 (데모 = 리바랩스 정량, DB 불필요)
npm run dev &
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --no-pdf-header-footer --print-to-pdf=/tmp/web.pdf --virtual-time-budget=25000 \
  "http://localhost:3000/viewer"

# 2) 찾는 페이지 번호 알아내기
pdftotext -layout /tmp/web.pdf /tmp/web.txt   # 텍스트에서 장 제목 검색

# 3) 우리 결과 / 원본을 같은 배율로 이미지화해 눈으로 대조
pdftoppm -jpeg -r 60 -f <쪽> -l <쪽> /tmp/web.pdf /tmp/web
```
