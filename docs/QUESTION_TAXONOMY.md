# 문항 유형 → 분석 → 섹션 매칭 (Phase 0 진단)

범용 보고서 생성의 1단계. 실제 raw data 4종을 대조해 "어떤 문항일 때 어떤 정량·정성 분석이
나오고, 그 결과가 어느 섹션으로 가는가"를 확정한다. 이 문서가 확정되기 전에는 인벤토리·
분석·섹션배정 코드를 쓰지 않는다.

## 1. 핵심 발견 — 유형이 같아도 섹션이 다르다

리바랩스에서 아래 문항은 **전부 같은 유형**(0~10 척도 + 다음 컬럼이 "위와 같이 평가한 이유")
인데 섹션은 전부 다르다.

| 문항 | 유형 | 섹션 |
|---|---|---|
| `‘펫과의 산책’ 기능에 대해 얼마나 만족하시나요?` | 척도+이유 | Ⅲ 기능별 경험 |
| `경험하신 걷기 기반 서비스에 대해 얼마나 만족하시나요?` | 척도+이유 | Ⅱ 인적사항(유사 서비스 경험) |
| `기능적 가치 영역 만족` | 척도+이유 | Ⅴ 4대 가치 |
| `실용성1) 캣독런의 조작이 [불편하다/편하다]` | 척도+이유 | Ⅵ UX 품질 |
| `전반적인 만족도(종합 점수)` | 척도+이유 | Ⅷ 종합만족도·NPS |

→ **유형(type)만으로는 섹션이 결정되지 않는다.** 유형은 "어떤 계산을 하는가"를,
**역할(role)** 은 "어느 섹션으로 가는가"를 결정한다. 두 단계로 분리해야 한다.

```
컬럼 → [유형 판정: 규칙] → 계산 방법 확정
     → [역할 판정: 신호 + LLM] → 섹션 확정
```

## 2. 문항 유형 (T) — 계산을 결정한다. 규칙으로 판정 가능

| 유형 | 판정 규칙 | 정량 산출 | 정성 산출 |
|---|---|---|---|
| **T1 범주형 단일선택** | 전부 비수치, 유니크 ≤ 10 | 빈도분포(n,%) | ✗ |
| **T2 범주형 복수선택** | 값에 `, ` 구분자 반복, 유니크 조합 다수 | 항목별 선택률(합 > 100%) | ✗ |
| **T3 수치 입력** | 전부 숫자, 유니크 다수, 상한 없음 | 평균/SD + 구간 분포 | ✗ |
| **T4 척도 + 이유** | 정수, 상한 5 또는 10, **다음 컬럼이 "이유" 패턴** | 평균/SD/점수분포 | ✓ Stage1(절 분리+극성) → Stage2(카테고리·인용·인사이트) |
| **T5 척도 단독** | 정수, 상한 5/10, 페어 이유 없음 | 평균/SD/분포 | ✗ |
| **T6 순위** | N개 연속 컬럼, 헤더가 `1위`…`N위`, 값이 항목명 | 평균 순위 → 상대중요도(FGI ±5) + 순위위치별 구성비 | ✗ |
| **T7 게이팅 Y/N** | 유니크 2개, 뒤 컬럼들의 n을 줄임 | 분포 + 하위 유효 n | 하위가 T4면 ✓ |
| **T8 자유서술 단독** | 텍스트, 페어 척도 없음 | 응답률 | ✓ 극성 없이 카테고리화 |
| **T9 의향 척도** | 0~10 + 헤더에 `NPS`/`추천 의향`/`사용 의향` | NPS 지수, 추천/중립/비추천 % | 이유 컬럼 있으면 ✓ |
| **T10 첨부/URL** | 값이 `http` 시작 | 응답률만 | ✗ (보고서 미노출) |

**파생 분석 2종** (문항이 아니라 조합에서 나온다)
- **교차분석**: T1(인적) × T4/T5 → 그룹별 평균 비교. 인적 T1이 2개 이상 + 척도 문항 3개 이상일 때만.
- **사분면**: T6 상대중요도 × T4 만족도. **항목명 집합이 매칭될 때만.**

> **실측 확인 — 사분면이 왜 케어클에서 안 그려지는가**
> 케어클 순위 항목: 사용편의성/피부개선효과/휴대성/안전성/기능다양성/가격경쟁력/제품디자인/브랜드신뢰성
> 케어클 기능 항목: SHOT/GLOW/EMS/모드전환/강도조절/LED컬러변경/인터페이스/보이스알림
> → 교집합 0. 리바랩스는 순위·기능 둘 다 같은 6개 기능명이라 교집합 6.
> 이 교집합 검사가 사분면 생성 조건이다. 제품군이 아니라 데이터가 결정한다.

### 척도 범위는 자동 감지해야 한다 (실측)

정리습관 한 파일 안에 **5점 척도와 10점 척도가 섞여 있다.**

- 10점: `‘정리의 목적’을 선택하는 과정이 얼마나 만족스러웠나요?` (min 5 max 10), `사용 편의성 만족`(5~10), `NPS`(0~10)
- 5점: `홈페이지 첫 화면에서 …쉽게 이해할 수 있었나요?`(2~5), `견적 결과가 어떻게 산출되었는지 이해할 수 있었나요?`(1~5), `견적 결과를 보고 서비스가 얼마나 신뢰할 만하다고 느끼셨나요?`(1~5)

문항 어미와 연동된다 — **"얼마나 만족스러웠나요" = 10점 / "…할 수 있었나요·이해하기 쉬웠나요" = 5점**.
축 범위·평균선·사분면 Y축을 0~10으로 고정한 현재 코드는 이 파일에서 전부 틀린다.

## 3. 문항 역할 (R) — 섹션을 결정한다

### 역할 카탈로그 (닫힌 집합)

| 역할 | 대상 섹션 | 4종에서의 실례 |
|---|---|---|
| `demographic` | Ⅱ 인적사항 | 나이·성별·OS·피부타입·거주형태·운전경력·차종 |
| `context` | Ⅱ 인적사항 | 걷기습관·시술경험·정비수준·정리 어려움·사용빈도/시간 |
| `prior_service` | Ⅱ 인적사항 | 경쟁 서비스 유무/이름/만족도/이유/장점/단점 |
| `feature` | Ⅲ 기능별 경험 | 펫과의 산책, SHOT, 고장 내용 진단 |
| `task_flow` | Ⅲ 기능별 경험 (변형) | **정리습관 전용** — 검색→목적→공간→물건양→견적 단계별 만족도 |
| `journey` | Ⅳ 고객 여정 | **케어클 전용** — 개봉→첫사용→1주→2주 |
| `purchase_factor` | Ⅳ/Ⅴ 핵심구매요소 | 핵심 요인 단일선택, 1~N위 순위 |
| `value` | Ⅴ/Ⅵ 가치 평가 | 4대 가치, **정리습관의 사용편의성/신뢰도/가격/소요시간** |
| `ux_quality` | Ⅵ UX 품질 | **리바랩스 전용** — 실용성1~4 / 즐거움1~4 |
| `overall` | Ⅷ 종합만족도·NPS | 전반적인 만족도(종합 점수) |
| `intent` | Ⅷ 종합만족도·NPS | NPS, 추천 의향, **이젠오토의 사용 의향** |
| `improvement` | Ⅷ 개선 아이디어 | 개선 아이디어 제안 |
| `meta` | 미노출 | 응답시간, 개인정보 동의, 휴대폰 뒷번호, 정산 방식, 이미지 업로드 |

### 역할 판정 신호 (raw data에 전부 있다 — 발명할 필요 없음)

1. **헤더 접두 마커** — `실용성N)`/`즐거움N)` → `ux_quality`, `N위` → `purchase_factor`,
   `~가치 영역 만족(도)` → `value`, `NPS` → `intent`
2. **따옴표로 감싼 고유명** — `‘SHOT’ 기능에 대해`, `‘펫과의 산책’ 기능에 대해` → `feature`.
   따옴표 안 문자열이 곧 항목명이다(현행 `extractFeatureNames`와 같은 원리)
3. **블록 연속성** — 같은 형태의 (척도+이유) 쌍이 3회 이상 연속 = 같은 역할의 한 블록.
   블록이 끊기는 지점이 역할 경계다. 4종 모두 이 규칙이 성립한다
4. **시점 표현** — `처음 받아보셨을 때`/`처음 열어보셨을 때`/`약 일주일 동안 사용해 보신 후`/
   `2주간 사용을 마치신 후` → `journey` (케어클에서 5개 연속으로 확인)
5. **플로우 동사** — `~을 선택하는 과정이`/`~정보를 입력하는 과정이`/`~을 확인하는 과정이`
   → `task_flow` (정리습관에서 5개 확인)
6. **게이팅 앵커** — `~경험이 있으신가요?`/`~사용해 보신 적이 있나요?` 직후 블록 = `prior_service`

→ 1~2·4~6은 규칙으로 잡히고, 애매한 컬럼만 LLM에 넘긴다. **LLM은 섹션을 발명하지 않고
위 13개 역할 중 하나를 고른다.**

| NPS | `nps` | T9 |
| 섹션 해석문 | `text` | 전 섹션 |

## 5. 섹션 카탈로그 — 발행 보고서 2종으로 이미 검증됨

| 섹션 | 리바랩스 9장 | 케어클 8장 | 생성 조건 |
|---|---|---|---|
| Ⅰ 개요 | ✓ | ✓ | 항상 |
| Ⅱ 인적 사항 및 특성 조사 | ✓ | ✓ | `demographic` ≥ 1 |
| Ⅲ 기능별 고객 경험 평가 | ✓ | ✓ | `feature` 또는 `task_flow` ≥ 1 |
| Ⅳ 고객 여정 기반 경험 평가 | — | ✓ | `journey` ≥ 3 |
| Ⅴ 핵심 구매 요소 | ✓ | ✓ | `purchase_factor` ≥ 1 |
| Ⅵ 4대 가치 만족도 → **가치 평가** | ✓ | ✓ | `value` ≥ 2 |
| Ⅶ 사용자 경험 품질 평가 | ✓ | — | `ux_quality` ≥ 3 |
| Ⅷ 교차 분석 | ✓ | — | 인적 T1 ≥ 2 **且** 각 그룹 n ≥ 5 |
| Ⅸ NPS 지수 및 종합 만족도 | ✓ | ✓ | `overall` 또는 `intent` ≥ 1 |
| Ⅹ 종합 결과 및 제언 | ✓ | ✓ | 항상 |

에이전트는 이 10개에서 **고르고 드롭만** 한다. 번호는 남은 섹션 순서대로 자동 재부여.
어디에도 안 맞는 문항은 "기타 조사 결과"로 흘려보내고 사람이 옮긴다.

> "4대 가치 만족도"는 **"가치 평가"** 로 일반화해야 한다. 이젠오토는 심미적 대신 **재미적**이고,
> 정리습관은 4대 가치 자체가 없고 사용편의성/신뢰도/가격/소요시간 4축을 쓴다. 항목명·개수를
> 하드코딩하면 세 데이터셋 중 두 개가 깨진다.

## 7. 실측 함정

- **정리습관 컬럼 36·37 헤더가 둘 다 `해당 서비스에서 만족스러웠던 점은 무엇이었나요?`**
  인데 36은 숫자 척도(2~10), 37은 자유서술이다. **원본 설문의 라벨 오류.**
  → 헤더 텍스트만 믿으면 안 되고 **값의 실제 타입으로 유형을 판정해야 한다.**
- 정리습관 경쟁 서비스 블록은 게이팅으로 n=46 → **n=12**. 유효 n을 섹션에 명시해야 한다.
- 케어클 순위는 8개, 리바랩스는 6개. 상대중요도 FGI 공식(`5 − 10×(평균순위−1)/(N−1)`)이
  N에 무관하게 ±5로 나오는지 두 N에서 재확인할 것.
- 케어클·정리습관은 성별 유니크 1(여성). 교차분석 조건에 "그룹 2개 이상 且 각 n ≥ 5"를
  넣지 않으면 한 칸짜리 그래프가 나온다.

## 8. 파일 유효성 검증의 새 기준

컬럼 위치 검사가 사라지므로 대체 기준이 필요하다.

- 응답자 행 ≥ 20
- 유형 판정 성공률 ≥ 80% (미판정 컬럼이 20% 넘으면 거부)
- 척도 문항(T4/T5/T9) ≥ 3
- `improvement` 또는 `overall` 중 최소 1개 존재
