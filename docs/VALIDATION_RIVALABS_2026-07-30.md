## 5. 발견된 프롬프트·입력 조립 결함

### P0. 대표 인사이트 선택이 빈도순이 아님

- `negativeInsights()`와 `insightsFor()`는 polarity 필터 후 바로 `slice()`한다.
- DB 카테고리 정렬 순서는 반복 빈도나 `clause_count` 기준이 아니다.
- 그 결과 모델에 전달되는 “대표 불만”이 실제 다빈도 불만이 아닐 수 있다.

개선:

- `clause_count` 내림차순을 기본으로 정렬한다.
- 동률은 question order, category label 순으로 고정해 재현성을 확보한다.

### P0. `repeatedComplaints()`가 반복 횟수를 세지 않음

- 현재 구현은 개선 아이디어 카테고리와 기능 부정 카테고리를 이어 붙인 뒤 앞 6개를 선택한다.
- 실제 반복 언급 횟수, 질문 간 재등장 횟수, 응답자 수를 계산하지 않는다.
- 입력 필드명 `반복_불만`과 실제 데이터의 의미가 다르다.

개선:

- 정규화된 주제 key로 카테고리를 묶는다.
- `clause_count`, 질문 간 등장 수, 응답자 수를 함께 전달한다.
- 반복 근거가 없는 경우 모델이 “반복적으로 언급됨”을 쓰지 못하게 한다.

### P1. 인과·역할 서술이 근거보다 강함

- “직결”, “중심축”, “기본 신뢰 요건”, “첫인상을 좌우” 등은 원문 근거가 없으면 인과 추론이다.

개선:

- 입력에 직접 인용 또는 해당 역할을 설명하는 인사이트가 있을 때만 허용한다.
- 그 외에는 “함께 확인됨”, “관련 불만이 확인됨”, “상대적으로 낮게 평가됨”처럼 관찰형 표현을 사용한다.

### P1. 낮은 선택률의 의미를 잘못 해석할 수 있음

- 구매요소 1%를 “기본 요건”으로 해석한 사례가 있다.

개선:

- 낮은 선택률은 “구매 결정 영향이 제한적으로 나타남”까지만 허용한다.
- 기본 요건, 위생 요인, 필수 요건 같은 해석은 별도 정성 근거가 있을 때만 허용한다.

### P1. 결과 요약의 시장성 프레임이 모든 섹션에 과도하게 적용될 수 있음

- 원본은 시장성·구매 전환 프레임을 핵심구매요소, NPS, 최종 결론에 집중한다.
- 기능, 4대 가치, UX의 모든 문장을 구매 전환으로 연결하면 원본보다 과잉 해석이 된다.

개선:

- 각 섹션은 먼저 해당 섹션의 관찰 사실을 독립적으로 요약한다.
- 시장성 연결은 핵심구매요소, NPS, 최종 종합 결론에서만 수행한다.

### P2. 결과 요약·제언 호출 방식이 섹션 분석과 다름

- 섹션 분석은 스트리밍 가드를 사용한다.
- 결과 요약과 제언은 아직 비스트리밍 `generateText` 경로다.

개선:

- 품질 변경 없이 요청 방식만 공통 스트리밍 가드로 통일한다.
- 사용량 기록을 연결해 실제 시간·입력 토큰·출력 토큰·비용을 결과별로 남긴다.
