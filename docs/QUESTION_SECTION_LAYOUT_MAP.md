# 문항 → 섹션 → 레이아웃 매칭 카탈로그

섹션 분류 에이전트의 **판정 기준표**이자, 판정 결과를 렌더러가 소비하는 **레이아웃 계약**이다.
raw data의 문항 하나하나가 어느 섹션으로 가고, 그 섹션이 어떤 그래프·표·템플릿으로 그려지는지를
실제 4개 데이터셋(리바랩스·케어클·이젠오토·정리습관)의 문항 원문으로 전부 예시화했다.

유형 판정 규칙·척도 감지·검증 기준은 [QUESTION_TAXONOMY.md](./QUESTION_TAXONOMY.md) 참조.
이 문서는 **"그래서 어떤 섹션의 어떤 레이아웃에 꽂히는가"** 만 다룬다.

---

## 0. 레이아웃 블록 카탈로그

`lib/report/sections.ts`에 이미 존재하는 블록. **새로 만들 블록은 없다.**

| 코드 | 블록 `kind` | 생김새 | 입력 |
|---|---|---|---|
| **L1** | `chart` | 세로 막대 + 값 라벨 + y축 그리드 | `{label, value}[]`, 축 min/max |
| **L1a** | `chart` + `averageLine` | 위 + 전체 평균 빨간 가로선 | + 평균값 |
| **L2** | `stacked-bar` | 가로 누적 막대 (행별 구성) | 행 × 세그먼트(값) |
| **L3** | `grouped-bar` | 항목별 여러 시리즈 나란히 | 시리즈 × 카테고리 |
| **L4** | `radar` | 방사형 (단일 시리즈) | 축 라벨[] + 값[] |
| **L4a** | `radar` overlay | 방사형 (다중 시리즈 + 범례) | 시리즈[] |
| **L5** | `rank-composition` | 순위별 가로 누적 막대 + 범례 | 순위 × 항목 구성비 |
| **L6** | `quadrant` | 중요도×만족도 사분면 산점도 | `{name, importance, satisfaction}[]` |
| **L6a** | `priority-reference` | 9칸 우선순위 기준 이미지 + 판정표 | (고정) |
| **L7** | `nps` | NPS 척도 이미지 + 지수 + 3구간 % | 추천/중립/비추천 % |
| **L8** | `polarity` | 긍정·부정·중립 3분할 가로 막대 | 3개 % |
| **L9** | `table` | 일반 표 (헤더 + 행) | headers[], rows[][] |
| **L9a** | `row-group` | 전치형 순위표 (항목을 열로) | headers[], rows[][] |
| **L10** | `heading` | 장/절/문항 제목 (`variant: numbered / question`) | 번호 + 텍스트 |
| **L11** | `rich-static` | 정성 서술 HTML (카테고리·인용·인사이트·해석) | HTML |
| **L12** | `text` | 편집 가능한 단문 (pending 표시 지원) | HTML |

### 정성 결과 전용 조합 템플릿 (L8+L11)

문항 하나의 정성 분석 결과는 **항상 이 형태**로 렌더된다 (`qualitativeBlocks()`):

```
L10  Q9. ‘펫과의 산책’ 기능에 대해 얼마나 만족하시나요?     ← 문항 제목
L8   [긍정 26.6%][부정 70.4%][중립 3.0%]                  ← 극성 막대
L11  ┌ 1. 긍정 의견 (26.6%)          ← 극성 배너(연보라)
     │  [산책 유도 효과]             ← 카테고리 (대괄호)
     │  "원래는 산책을 안하는데…"     ← 인용문 (따옴표)
     │  → 걷기 동기 부여가 핵심 만족  ← 인사이트 (화살표)
     ├ 2. 부정 의견 (70.4%)  …
     └ 3. 중립 의견 (3.0%)   …
```

**개선 아이디어만 2단 변형**: `[대분류]` → `<소분류>` → 인용 다수, 인사이트·극성 없음.

## 1. 섹션별 레이아웃 템플릿

에이전트가 섹션을 확정하면 렌더러는 아래 시퀀스를 그대로 찍는다.

### S1. 개요 — 항상 생성
```
L10 1 | 제품 소개              → L9(제품정보 표)
L10 2 | 사용성 테스트 진행 일정  → L9(기간·대상·담당자)
L10 3 | 사용성 테스트 설문 항목  → L9(단계 병합셀 × 문항 목록)   ← 인벤토리에서 자동 생성
```

### S2. 인적 사항 및 특성 조사 — `demographic` ≥ 1
```
per demographic 문항:
  L10 Q{n}. {문항 원문}
  L1  세로막대 (범주별 %)                    ← T1 범주형
  또는 L1 세로막대 (구간별 %)                 ← T2 수치입력(나이 → 10대/20대/…)
L2  성별 × 연령대 교차 누적막대  ← 성별·나이 둘 다 있을 때만
L9  성별 × 연령대 교차표(명)
per context 문항:  L10 + L1
prior_service:     L9(경험 유무·서비스명·만족도 요약)
```

### S3. 기능별 고객 경험 평가 — `feature` 또는 `task_flow` ≥ 1
```
L10 1 | {기능/단계}별 고객 경험 조사 결과
L1a 기능별 만족도 (내림차순 + 전체 평균선)
L9a 기능별 만족도 순위 종합 (전치 순위표, 1위 파랑/최하 주황)
per 기능:
  L10 Q{n}. {문항 원문}
  L8  극성 막대
  L11 카테고리·인용·인사이트
L10 2 | {기능/단계}별 고객 경험 분석
L11 섹션 해석문 (LLM)
```

### S4. 고객 여정 기반 경험 평가 — `journey` ≥ 3
```
L10 1 | 고객 여정 기반 경험 평가 조사 결과
L1  시점별 평균 (x축 = 개봉 → 첫사용 → 1주 → 2주, 시간 순서 유지)
L9  시점별 평균/SD 표
L10 2 | 고객 여정 기반 경험 평가 결과 분석
L11 변곡점 해석 (LLM)
```

### S5. 핵심 구매 요소 — `purchase_factor` ≥ 1
```
L10 1 | 핵심구매요소 조사 결과
L1  핵심 요인 단일선택 분포 (%)          ← 단일선택 문항이 있을 때
L9  No/요인/응답수/비율 표
L5  순위 구성 누적막대 (1위~N위)         ← 순위 문항이 있을 때
L9a 항목별 중요 순위 종합 (전치 순위표)
L6  중요도 × 만족도 사분면                ← 순위 항목명 ∩ 기능명 ≥ 3 일 때만
L6a 영역별 참고 지표
L10 2 | 핵심구매요소 분석
L11 섹션 해석문 (LLM)
```

### S6. 가치 평가 — `value` ≥ 2
```
L10 1 | {가치축 이름} 조사 결과
L1a 가치별 평균 (전체 평균선)
L9  가치별 평균/표준편차 표
per 가치:
  L10 Q{n}. {문항 원문}
  L8 + L11
L10 2 | {가치축 이름} 조사 결과 분석
L11 섹션 해석문 (LLM)
```

### S7. 사용자 경험 품질 평가 — `ux_quality` ≥ 3
```
L10 1 | 사용자 경험 품질 평가 결과
L4  [전체] 레이더
L4  [실용성] 레이더        ← 그룹 접두가 2개 이상이면 그룹별로 분리
L4  [즐거움] 레이더
L9  그룹별 점수표 (열별 최대 파랑/최소 주황)
L10 2 | 사용자 경험 품질 평가 결과 분석
L11 섹션 해석문 (LLM)
```

### S8. 교차 분석 — 인적 T1 ≥ 2 且 각 그룹 n ≥ 5
```
L10 1 | 교차 분석 결과 및 분석
L3  연령대별 기능 만족도 차이
L3  연령대별 가치 만족도 차이
L3  성별 기능 만족도 차이
L3  성별 가치 만족도 차이
L4a 성별 UX 품질 레이더 오버레이     ← ux_quality 있을 때만
L11 [전반적 만족도 경향] (규칙 기반)
```

### S9. NPS 지수 및 종합 만족도 — `overall` 또는 `intent` ≥ 1
```
L10 1 | {NPS/추천의향} 및 종합 만족도
L7  NPS 게이지 + 지수
L11 척도 설명 + 추천/중립/비추천 정의 (고정 템플릿)
L11 판단 불렛 (시장성·구매전환, 계산값으로 동적 생성)
L1  사용 의향 / 추천 의향 분포          ← intent 문항이 2개일 때 각각
L9  NPS 요약표
L8 + L11  종합 만족도 정성
L10 2 | 개선 아이디어
L11 개선 아이디어 2단 카테고리 (대분류 → 소분류 → 인용)
```

### S10. 종합 결과 및 제언 — 항상 생성
```
L10 1 | 사용성테스트 결과 요약
L11 결과 요약 (LLM, Tier 1)
L6 + L6a  사분면 재사용                 ← S5에서 생성됐을 때만
L9  기능별 고객 경험 평가 (기능/평균만족도/상대중요도/긍·중·부 %)
L10 2 | 개선 전략 제언
L11 개선 전략 제언 (LLM, 체크포인트 대상)
L10 3 | 기능별 고객 제언 종합
L9a 기능별 As-is → To-be 표
```

## 2. 문항별 매칭 카탈로그 (본체)

각 역할마다: **판정 신호 → 4종 실례 → 정량 → 정성 → 섹션 → 레이아웃**

---

### R1. `demographic` — 응답자 속성

**신호**: 설문 앞부분(첫 척도 문항 이전) 위치 + 범주형/수치 + 이유 컬럼 없음

| 데이터셋 | 문항 원문 | 유형 | 정량 |
|---|---|---|---|
| 리바랩스 | `나이를 입력해주세요` | T3 수치 | 평균/SD + 10대/20대/30대/40대↑ 구간 분포 |
| 리바랩스 | `성별을 선택해주세요` | T1 | 빈도 % |
| 리바랩스 | `현재 사용하시는 스마트폰 운영체제를 선택해주세요` | T1 (iOS/안드로이드) | 빈도 % |
| 케어클 | `피부 타입` | T1 (건성/지성/복합성/민감성/해당없음) | 빈도 % |
| 이젠오토 | `이전 경력을 선택해주세요` (운전 경력) | T1 (1년 미만 ~ 10년 이상) | 빈도 % |
| 이젠오토 | `현재 소유하고 있는 차종을 적어주세요` | T8 자유서술 | **미노출** (자유입력, 집계 불가) |
| 정리습관 | `현재 거주 형태를 선택해주세요` | T1 (아파트/빌라·단독/원룸) | 빈도 % |
| 정리습관 | `함께 거주 중인 가족 구성원 수를 선택해주세요` | T1 (1~4명 이상) | 빈도 % |

**정성** ✗ → **섹션 S2** → **레이아웃 `L10 + L1`** (문항당 세로막대 1개)
**추가**: 성별·나이가 둘 다 있으면 `L2`(성별×연령 누적막대) + `L9`(교차표) 자동 생성

> 차종·차량번호처럼 **자유입력 텍스트인 인적사항은 집계 불가**라 `meta`로 떨어뜨린다.
> 판정 규칙: T1인데 유니크 수가 응답자 수의 50%를 넘으면 자유입력으로 간주.

### R2. `context` — 사용 맥락·사전 태도

**신호**: 인적사항 블록 직후, 범주형, 제품 사용 이전의 습관/경험/태도를 묻는다

| 데이터셋 | 문항 원문 | 값 예시 |
|---|---|---|
| 리바랩스 | `하루 평균 걷는 시간은 어느 정도인가요?` | 15분 미만 / 15~30분 / … / 2시간 이상 |
| 리바랩스 | `일주일에 몇 일 정도 산책을 하시나요?` | 전혀 / 1~2일 / 3~4일 / 매일 |
| 케어클 | `케어클의 ‘테크핏’을 체험하기 전, 다른 홈케어 뷰티 디바이스를 사용하고 계셨나요?` | 사용 안 함 / 주 1-2회 / 주 3-4회 / 주 5일↑ |
| 케어클 | `피부과에서 레이저/고주파 시술을 받은 경험이 있으신가요?` | 받아본 적 없음 / 가끔 / 정기적 / 과거엔 |
| 케어클 | `‘테크핏’을 어느 정도 주기로 사용하셨나요?` | 주 2~5회 이상 |
| 케어클 | `‘테크핏’을 한 번 사용하실 때, 사용 시간은 어느 정도 되시나요?` | 5~10분 / … / 30분 이상 |
| 이젠오토 | `연 주행거리(km)가 얼마나 되나요?` | 자유 수치 → 구간화 |
| 이젠오토 | `자가 차량 정비에 대한 경험의 수준을 선택해주세요` | 1단계 경험 없음 / 2단계 단순 소모품 교환 / 3단계 기본 정비 |
| 정리습관 | `평소 집 정리나 수납이 어렵다고 느낀 적이 있으신가요?` | 매우 그렇다 ~ 전혀 그렇지 않다 (5단) |
| 정리습관 | `집 정리를 할 때 가장 어려운 점은 무엇인가요?` | 어디서부터 시작 / 수납공간 부족 / 유지 어려움 / 시간 부족 |
| 정리습관 | `현재 본인 상황에 해당하는 항목을 모두 선택해주세요 (중복 선택)` | **T2 복수선택** — 기혼 / 이사 예정 / 해당 없음 |

**정량**: 빈도 % (T2는 항목별 선택률, 합 > 100%) **정성** ✗
→ **섹션 S2** → **레이아웃 `L10 + L1`**

> 정리습관의 `평소 집 정리나 수납이 어렵다…`, `가장 어려운 점` 2개는 **문제 정의 근거**로
> S10 결과 요약에서 재인용할 가치가 있다. 인벤토리에 `reusableInSummary: true` 플래그를 둔다.

### R3. `prior_service` — 경쟁/유사 서비스 경험

**신호**: 게이팅 Y/N (`~사용해 보신 적이 있나요?` / `~경험이 있으십니까?`) + 그 뒤에 딸린 종속 컬럼들

| 데이터셋 | 문항 원문 | 하위 유형 |
|---|---|---|
| 리바랩스 | `캣독런 외에 다른 걷기 기반 서비스를 사용해 보신 적이 있나요?` | T7 게이팅 |
| 리바랩스 | `어떤 걷기 기반 서비스를 사용해 보셨나요?` | T8 자유서술 → 서비스명 빈도 |
| 리바랩스 | `경험하신 걷기 기반 서비스에 대해 얼마나 만족하시나요?` | T4 척도+이유 (n 축소) |
| 케어클 | `테크핏 외에 다른 홈케어 디바이스를 사용하신 경험이있으십니까?` | T7 |
| 케어클 | `어떤 뷰티 디바이스를 사용해 보셨나요?` | T8 |
| 케어클 | `경험하신 제품에 대해 얼마나 만족하시나요?` | T4 (n=19/27) |
| 이젠오토 | `차량 정비 관련하여 과거에 사용하던 서비스 중 만족하는 서비스가 있으십니까?` | T7 |

**신호**: 같은 대상에 대한 만족도를 **시간 표현**과 함께 반복해 묻는다.
`처음 ~했을 때` / `N주 후` / `N일 동안 사용해 보신 후`

| 데이터셋 | 문항 원문 | 시점 |
|---|---|---|
| 케어클 | `‘테크핏’이 담긴 박스를 처음 받아보셨을 때 첫인상은 어떠셨나요?` | t0 개봉 전 |
| 케어클 | `‘테크핏’이 담긴 박스를 처음 열어보셨을 때 느낌은 어떠셨나요?` | t1 개봉 |
| 케어클 | `‘테크핏’을 처음 사용하셨을 때 전반적인 과정은 어떠셨나요?` | t2 첫 사용 |
| 케어클 | `약 일주일 동안 사용해 보신 후, 제품에 대한 만족도는 몇 점인가요?` | t3 1주 |
| 케어클 | `2주간 사용을 마치신 후, 제품에 대한 만족도는 몇 점인가요?` | t4 2주 |

**정량**: 시점별 평균/SD + **인접 시점 간 증감(Δ)**. 케어클 원본은 `7.16점으로 -1.92점 하락`처럼
Δ를 본문에 쓴다 → 변곡점 자동 검출(최대 하락 구간).
**정성**: 이유 컬럼 없음 → ✗
→ **섹션 S4** → **레이아웃**
```
L1  시점별 평균 (x축 = 시간 순서, Δ를 막대 위에 병기)
L9  시점별 평균/SD/Δ 표

> 순서 키가 필요하다. 컬럼 순서(설문 작성 순서)를 1차 기준으로 쓰고 시간 표현으로 검증한다.

### R7. `purchase_factor` — 구매/이용 결정 요인

**신호 A (단일선택)**: `가장 크게 영향을 미칠 수 있는 {핵심 요인|요인}은 무엇이라고 생각하시나요?`
**신호 B (순위)**: 헤더가 `1위`…`N위`이고 값이 항목명

| 데이터셋 | 문항 원문 / 형태 | 항목 |
|---|---|---|
| 리바랩스 | `‘캣독런’ 서비스를 이용함에 있어 가장 크게 영향을 미칠 수 있는 핵심 요인은 무엇이라고 생각하시나요?` | 성취·보상 / 시각 디자인 / 사용 편의성 / 무료·유료 콘텐츠 … (6지) |
| 리바랩스 | `1위`~`6위` | **기능명 6개** (= R4 항목과 동일) |
| 케어클 | `1위`~`8위` | 사용 편의성 / 피부 개선 효과 / 안전성 / 휴대성·보관 / 기능 다양성 / 가격 경쟁력 / 제품 디자인 / 브랜드 신뢰성 |
| 이젠오토 | `위일이 서비스를 이용함에 있어서 가장 영향을 미칠 수 있는 핵심 요인은 무엇이라고 생각하십니까?` | 콘텐츠 신뢰도·정확도 / 사용 편의성 / 가격 경쟁력 / 디자인(UX·UI) / 커뮤니티 / 예약 / 리워드 … |
| 정리습관 | `‘정리습관’ 서비스를 이용할 때 가장 크게 영향을 미칠 수 있는 요인은 무엇이라고 생각하시나요?` | 가격(비용) / 서비스 신뢰도 / 사용 편의성 / 소요 시간 (4지) |

**정량**
- 단일선택 → 빈도 %
- 순위 → 평균 순위 → **상대중요도 = 5 − 10×(평균순위−1)/(N−1)** (FGI 공식, N 무관 ±5)
- 순위 → 순위 위치별 항목 구성비
- **사분면**: 순위 항목명 ∩ `feature` 항목명 ≥ 3일 때만

**정성**: 이유 컬럼 있으면 ✓ (리바랩스 `…이유는 무엇인가요?(copy)`, 정리습관 동일)
→ **섹션 S5** → **레이아웃**
```
L1  핵심 요인 분포 (%)                    ← 단일선택 있을 때
L9  No/요인/응답수/비율 표
L5  순위 구성 누적막대                     ← 순위 있을 때
L9a 항목별 중요 순위 종합 (전치 순위표)
L6 + L6a  사분면 + 참고 지표               ← 교집합 ≥ 3 일 때만
L11 섹션 해석문
```

| 데이터셋 | 단일선택 | 순위 | 사분면 |
|---|---|---|---|
| 리바랩스 | ✓ | ✓(기능명) | **✓** 교집합 6 |
| 케어클 | ✗ | ✓(구매요소명) | **✗** 교집합 0 |
| 이젠오토 | ✓ | ✗ | ✗ |
| 정리습관 | ✓ | ✗ | ✗ |

> 사분면이 안 그려지는 데이터셋에서는 **"기능 만족도 내림차순 + 핵심 요인 분포"를 나란히
> 놓은 L1 2개**로 대체한다. 빈 자리를 만들지 않는다.

> 쓰면 거짓말이 된다.
>
> **정리습관의 4축은 R7 핵심 요인 선택지와 문구가 같다** (가격/신뢰도/사용편의성/소요시간).
> 즉 "무엇이 중요한가(선택)"와 "그게 얼마나 만족스러운가(척도)"가 짝을 이룬다 →
> **이 경우 사분면(중요도×만족도)을 그릴 수 있다.** 순위 문항이 없어도 단일선택 비율을
> 중요도 축으로 쓰면 된다. 교집합 4.

**축 라벨은 접두를 뗀 뒷부분**에서 뽑는다 → `조작 편의성`, `흐름 자연스러움`, `재미·흥미도` …
(현행 `extractUxQualityNames`)

**정량**: 항목별 평균, 그룹별 평균, 전체 평균 **정성**: ✓ T4 표준
→ **섹션 S7** → **레이아웃**
```
L4  [전체] 레이더 (8축)
L4  [실용성] 레이더 (4축)
L4  [즐거움] 레이더 (4축)

### R11. `intent` — 사용/추천 의향

**신호**: 헤더가 `NPS` 또는 `~추천할 의향` / `~사용하실 의향`

| 데이터셋 | 문항 원문 | 처리 |
|---|---|---|
| 리바랩스 | `NPS` | NPS 지수 |
| 케어클 | `NPS` | NPS 지수 |
| 정리습관 | `NPS` | NPS 지수 |
| 이젠오토 | `본 서비스를 체험해보셨을 때, 위일이 앱을 사용하실 의향이 얼마나 있습니까?` | **사용 의향** — 평균 + 분포 |
| 이젠오토 | `본 서비스를 체험해보셨을 때, 위일이 앱을 가장 친한 친구 또는 형제, 자매, 지인에게 추천할 의향이 있습니까?` | **추천 의향** = NPS로 계산 |

**정량**: NPS 지수, 추천(9~10)/중립(7~8)/비추천(0~6) %. 의향 문항이 2개면 각각 분포 + NPS는 추천 쪽만
**정성**: 이유 컬럼 있으면 ✓
→ **섹션 S9** → **레이아웃**
```
L7  NPS 게이지 (고정 이미지 + 지수)
L11 척도 설명 (Bain 정의, 고정 템플릿)
L11 판단 불렛 (부호·중립비율로 동적 생성)
L1  사용 의향 분포                        ← intent 2개일 때만
L9  NPS 요약표
L8 + L11  이유 정성
```

> **헤더가 `NPS`가 아니어도 잡아야 한다.** 이젠오토처럼 문장형으로 물으면 문자열 매칭이
> 실패한다. `추천`+`의향` 동시 포함 + 0~10 척도를 보조 신호로 쓴다.

## 4. 에이전트 출력 계약

섹션 분류 에이전트는 아래 JSON만 낸다. 레이아웃은 고르지 않는다 — 역할이 정해지면
§1의 템플릿이 결정론적으로 따라온다.

```jsonc
{
  "questions": [
    {
      "columnIndex": 9,
      "text": "‘펫과의 산책’ 기능에 대해 얼마나 만족하시나요?",
      "type": "T4",            // 규칙 판정 결과 (에이전트는 검증만)
      "role": "feature",       // ← 에이전트가 정하는 유일한 값
      "itemName": "펫과의 산책", // 항목명 (따옴표/접두에서 추출)
      "groupKey": null,        // ux_quality의 "실용성" 등
      "orderKey": null,        // journey/task_flow의 순서
      "reasonColumn": 10,
      "scaleMax": 10,
      "confidence": 0.95
    }
  ],
  "sections": [
    { "id": "S3", "title": "기능별 고객 경험 평가", "questionIndexes": [9,11,13,15,17,19] }
  ],
  "dropped": [
    { "id": "S4", "reason": "journey 역할 문항 0개" },
    { "id": "S8", "reason": "성별 유니크 1(여성 100%) — 비교 그룹 부족" }
  ],
  "unassigned": [
    { "columnIndex": 6, "text": "현재 소유하고 있는 차종을 적어주세요", "reason": "자유입력 텍스트, 집계 불가" }
  ]
}
```

**검증 규칙**
- `role`은 R1~R13 중 하나여야 한다 (자유 문자열 금지)
- `confidence < 0.7`인 문항은 카드에서 사용자 확인을 받는다
- `unassigned`가 전체의 20%를 넘으면 파일을 거부한다
