## 0. 발행 보고서가 실제로 쓰는 "단계" (원문 그대로)

| 리바랩스 (Q1~Q37) | 케어클 (Q1~Q37) |
|---|---|
| 인적 사항 및 특성 조사 (Q1~Q5) | 인적 사항 및 특성 · **경험** 조사 (Q1~Q9) |
| 기능별 고객경험 평가 (Q6~Q12) | 기능별 고객경험 평가 (Q10~Q17) |
| **경쟁재 경험 조사** (Q13~Q15) | *(위 Q6~Q9에 통합)* |
| 핵심구매요인 파악 (Q16~Q22) | **고객 여정 기반 경험** (Q18~Q24) |
| 가치 만족도 평가 (Q23~Q26) | 핵심구매요인 파악 (Q25) |
| 사용자 경험 품질 평가 (Q27~Q34) | 가치 만족도 평가 (Q26~) |
| 종합 만족도 (Q35) | 종합 만족도 |
| 구매/추천 의향 조사 (Q36) | 구매/추천 의향 조사 |
| 개선 아이디어 (Q37) | 개선 아이디어 |

> **단계 = 보고서 목차의 단위**다. 두 보고서 모두 이 단계를 그대로 장(章)으로 올린다.
> 경쟁재 조사만 리바랩스는 별도 단계, 케어클은 인적사항에 흡수 — **배치 섹션은 어차피 Ⅱ장으로 동일**하므로
> 통합 카탈로그에서는 별도 단계로 두고 Ⅱ장에 넣는다.

| 단계 | raw data 컬럼 | 개수 |

| 핵심구매요인 파악 | Q7 6개 기능 **순위**(열=기능, 값=`3위`) / Q8 6개 구매요소 **순위**(사용편의성·디자인·가격경쟁력·기술트렌드·첨삭정확도·이용자유도) | 6 + 6 |

| 가치 만족도 평가 | Q15 기능적 / Q16 경제적 / Q17 재미적 / Q18 사회·공공적 | 4 |
| 종합 만족도 | Q19 전반적인 만족도 + 이유 | 1쌍 |
| 구매/추천 의향 조사 | Q20 추천 의향 + 이유 + **누구에게 추천하고 싶은가**(자유서술) | 3 |
| 개선 아이디어 | Q21 활용도 향상 방안 / Q22 자유 아이디어 (2문항) | 2 |
| **기술 요청 질문** | Q23 AI 첨삭 만족도 / Q24 사용설명서 도움 만족도 / Q25 직관성 만족도 + 각 이유 | 3쌍 |

> **투블럭에이아이가 준 3가지 새 정보**
> ① 이유 컬럼이 **2개**(불편한 점 / 개선 포인트)로 쪼개진 형태
> ② 순위 문항의 **행렬 방향이 반대**(리바랩스·케어클은 `열=순위, 값=항목명`, 투블럭은 `열=항목, 값=순위`)
> ③ 핵심구매요소가 **순위 + 만족도 둘 다** 존재 → 기능이 아닌 **구매요소 축으로 사분면**을 그릴 수 있다

| **L18** | 전략 과제 도출 표 | `As Is`(영역·전략방향) → `To Be`(전략과제·세부수행방안) 4열, 전략과제 셀 색상 구분 | 리바랩스의 기능별 As-is→To-be(`L9a`)와 **다른 형식** |
| **L19** | 추천 대상 분포 | 카테고리별 세로 막대(단위: 명) | `Q20-1. 누구에게 추천하고 싶으신가요?` 자유서술 → 카테고리화 |

### 정성 블록 변형 3종 (중요)

| 형태 | 극성 구분 | 사용 보고서 |
|---|---|---|
| 3분할 | 긍정 / 부정 / 중립 | 리바랩스 · 케어클 |
| **2분할** | **만족 / 불편** | **투블럭** |
| 2단 카테고리 | 대분류 → 소분류 (극성 없음) | 전 보고서의 개선 아이디어 절 |

→ 피그마에서는 **극성 배너를 컴포넌트 variant로** 만들어야 함 (3분할/2분할 전환).

### 사분면이 2개 나올 수 있음

투블럭은 `기능별 상대 중요도-만족도 그래프`(Ⅱ장)와 `핵심구매요소별 상대 중요도-만족도 그래프`(Ⅲ장)를 **둘 다** 그린다.
`L6`+`L6a`는 한 보고서에 2회 반복될 수 있는 컴포넌트로 설계할 것.
