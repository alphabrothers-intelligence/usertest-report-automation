# 사용성테스트 결과보고서 자동화 방향 결정안

> 미팅 목적: 담당자에게 빈 질문을 전달하는 것이 아니라, 두 원본을 근거로 만든 권장안을 제시하고 선택·수정만 받는다.

## 1. 현재 확인된 사실

- 회사 표준 보고서 양식이 있으나, 실제 제공된 리바랩스·케어클 결과보고서와 일부 구성이 다르다.
- 프로젝트에 있는 `알파브라더스_기업명_사용성테스트_결과보고서_공양식.hwpx`는 2024년 기준 SW 공양식으로 확인됐다. 단순 빈 문서가 아니라 표지, 제품 소개, 설문 항목, 기능별 경험, 4대 가치, 핵심구매요소, NPS, 분석 결과, 개선방안 목차와 스타일이 포함돼 있다.
- 리바랩스는 SW/App형, 케어클은 실제품형의 기준 사례다.
- MVP는 SW/App형을 먼저 완성·검증한 뒤 실제품형으로 확장한다.
- PDF는 바로 출력할 수 있을 정도의 원본 재현도가 최우선이다.
- HWPX는 담당자의 후속 편집 원본이므로, 단순 데이터 덤프가 아니라 PDF와 같은 문서 구조·스타일을 가져야 한다.
- 최종 결정권자는 바쁘므로, 구현 담당자가 예시와 권장안을 준비하고 담당자는 선택·승인하는 방식이 적절하다.

### 핵심 결론

두 원본은 디자인이 전혀 다른 보고서가 아니라, **공통 골격에 제품유형별 분석 모듈이 추가된 구조**로 볼 수 있다.

- SW/App형: 사용자 경험 품질, 필요 시 교차분석
- 실제품형: 고객 여정 기반 경험 평가
- 공통: 개요, 응답자 특성, 기능 평가, 구매요소, 가치, NPS, 개선 아이디어, 종합 제언

## 3. 권장 SW MVP 표준 목차

장 번호는 포함되는 조건부 섹션에 따라 자동으로 다시 매긴다. 원본의 특정 로마 숫자를 데이터 모델에 고정하지 않는다.

### 필수 영역

1. 개요
   - 제품·서비스 소개
   - 사용성 테스트 대상과 일정
   - 설문 문항 구성
2. 응답자 특성
   - 연령, 성별 등 기본 특성
   - 서비스 사용 경험 등 프로젝트별 특성 문항
3. 기능별 고객 경험 평가
   - 기능별 만족도와 분포
   - 긍정·부정·중립 의견
   - 대표 인용문과 주요 개선 요구
   - 기능 중요도와 만족도를 함께 받은 경우 우선순위 분석
4. 핵심구매요소
   - 선택 분포와 순위
   - 구매 결정 관점의 해석
5. 가치·사용자 경험 평가
   - 4대 가치가 설문에 있을 경우 표시
   - 실용성·즐거움 등 UX 품질 문항이 있을 경우 표시
6. 종합 만족도 및 NPS
   - 종합 만족도
   - 추천·구매 의향
   - NPS 문항이 있을 경우 NPS
7. 개선 아이디어
   - 개선 요구 분류
   - 대표 의견과 우선 검토 항목
8. 종합 결과 및 제언
   - 핵심 결과 요약
   - 개선 전략 제언
   - 기능별 고객 제언 종합

### 조건부 영역

- 교차분석: 비교할 그룹과 충분한 표본이 있을 때만 포함
- 경쟁·유사 서비스 경험: 해당 문항이 있을 때만 포함
- 4대 가치: 해당 문항이 있을 때만 포함
- NPS: 표준 0~10점 추천 의향 문항이 있을 때만 포함
- 중요도-만족도 사분면: 기능 만족도와 중요도 순위가 모두 있을 때만 포함

### 데이터가 없을 때의 권장 원칙

- 설문에 없는 지표를 AI가 추정하거나 생성하지 않는다.
- 필수 의미 영역에 데이터가 없으면 섹션을 억지로 만들지 않고 제외한다.
- 담당자가 반드시 알아야 하는 누락이면 생성 전 검토 화면에서 알린다.
- 최종 목차와 장 번호는 실제 포함 섹션 기준으로 자동 생성한다.

## 3.1 공통 섹션은 동일한 결과 블록 사용

SW와 실제품에 공통으로 존재하는 섹션은 제품유형과 무관하게 같은 정보 구조와 템플릿을 사용한다.

### 기능별 고객 경험·만족도 문항 공통 블록

1. 질문 제목과 평가 대상
2. 유효 응답자 수
3. 평균·표준편차
4. 점수별 만족도 분포
5. 주요 키워드 워드클라우드
6. 상위 키워드 빈도표
7. 긍정·부정·중립 분포
8. 응답 요약
9. 극성별 대표 인용문과 상세 의견
10. 담당자 검수 상태

### 종합 만족도·NPS 공통 블록

1. 종합 만족도와 분포
2. 추천·중립·비추천 구성
3. NPS 산식과 결과
4. 주요 키워드
5. 극성별 응답 요약

## 3.2 워드클라우드 공통 적용 권장안

### 원본 확인 결과

- 리바랩스는 기능별 고객 경험 문항에 `주요 키워드 도출` 영역이 반복적으로 존재한다.
- 케어클은 `주요 키워드 도출`, `중요 키워드 빈도 활동 클라우드` 레이블과 배치 영역은 있으나 실제 워드클라우드 결과가 채워지지 않았다.
- 따라서 케어클이 워드클라우드를 구조적으로 배제했다기보다, 결과 영역을 계획했지만 완성본에서는 미구현한 것으로 판단할 수 있다.

### 권장 결정

SW·실제품 모두 주관식 응답이 있는 공통 문항에는 동일한 워드클라우드 블록을 적용한다.

다만 워드클라우드는 단독 분석 결과가 아니라 **응답 탐색을 돕는 보조 시각화**로 사용한다. 반드시 상위 키워드 빈도표와 대표 인용문을 함께 제공한다.

### 생성 조건

- 해당 문항에 유효 주관식 응답이 있을 것
- 무응답·의미 없는 단답을 제외한 뒤 분석 가능한 텍스트가 있을 것
- 최소 유효 응답 수 기준을 담당자와 확정할 것
- 기준 미만이면 빈 워드클라우드를 만들지 않고 `표본 부족으로 미생성`으로 표시할 것

### 전처리 규칙

- 조사 대상명·서비스명처럼 모든 응답에 반복되는 단어 제외
- `좋아요`, `없음`, `모르겠음` 등 불용어 사전 적용
- 같은 의미의 표현 통합
- 명사만 기계적으로 자르지 않고 핵심 구문도 보존
- 원문을 변경하지 않고 표시용 키워드만 정규화
- 담당자가 제외·통합 키워드를 수정할 수 있게 제공

### 표시 규칙

| 요소 | 권장 기준 |
|---|---|
| 키워드 수 | 상위 15~25개 |
| 크기 | 실제 언급 빈도에 비례 |
| 색상 | 긍정·부정 의미를 임의 부여하지 않고 브랜드 팔레트 사용 |
| 빈도표 | 키워드, 언급 건수, 전체 유효 응답 대비 비율 표시 |
| 근거 | 키워드를 포함한 대표 원문 확인 가능 |
| 주석 | 글자 크기는 중요도가 아니라 언급 빈도임을 명시 |

### 해석 시 주의사항

- 자주 나온 단어가 반드시 중요한 문제라는 뜻은 아니다.
- 긍정과 부정 문맥이 섞일 수 있으므로 워드클라우드만으로 극성을 판단하지 않는다.
- 유사어를 통합한 기준이 결과에 영향을 줄 수 있다.
- 표본이 작은 문항에서는 시각적 크기 차이를 과도하게 해석하지 않는다.
- 워드클라우드는 카테고리 분석·인용문·빈도표를 대체하지 않는다.

## 4. 실제품 확장안

SW MVP 검증 후 다음 모듈을 추가한다.

1. 고객 여정 단계 정의
   - 수령·개봉·첫 사용·반복 사용·사용 종료 등
2. 단계별 경험 평가
   - 만족도, 불편 요인, 긍정 요인, 인용문
3. 시간 경과 평가
   - 첫 사용, 1주, 2주 등 조사 설계에 존재하는 시점만 사용
4. 제품 속성 평가
   - 외관, 조작, 강도, 안전성, 패키징 등 프로젝트별 속성

실제품형도 공통 디자인 시스템을 사용하되, SW형의 UX 품질·교차분석을 무조건 복사하지 않는다.

## 5. 보고서 템플릿 권장안

### 권장: 회사 표준 양식 + 두 원본의 결과 표현 규칙

회사 표준 보고서 양식을 브랜드 기준으로 사용하고, 리바랩스·케어클에서 검증된 결과 블록을 결합한다.

현재 공양식은 버릴 대상이 아니라 **세 번째이자 가장 우선순위가 높은 브랜드 레퍼런스**다. 다만 2024년 공양식의 고정 목차를 그대로 유지할지, 2025년 리바랩스·케어클 완성본의 최신 목차·결과 표현으로 갱신할지는 담당자 승인이 필요하다.

| 요소 | 우선 기준 |
|---|---|
| 로고, 표지, 회사명, 발주처, 헤더·푸터 | 회사 표준 양식 |
| 기본 글꼴, 브랜드 색상 | 회사 표준 양식 우선, 없으면 두 원본 공통값 |
| 장·절 제목 계층 | 두 원본의 공통 구조 |
| 질문 결과, 차트, 표, 인용문 | 리바랩스·케어클 결과 블록 |
| 볼드·밑줄·기울임·화살표 | 의미 기반 공통 스타일 규칙 |
| 페이지 나눔과 목차 | 최종 포함 콘텐츠 기준 자동 생성 |

### HWPX 원본에서 글씨만 지우는 방식을 권하지 않는 이유

- 고정된 표 행·페이지 수·문항 수가 특정 프로젝트에 종속된다.
- 내용 길이가 달라지면 페이지 밀림과 표 넘침이 발생한다.
- SW와 실제품의 섹션 차이를 처리하기 어렵다.
- 빈 칸을 채우는 방식으로는 조건부 섹션을 안전하게 추가·제거하기 어렵다.

대신 HWPX 안의 스타일과 블록 구조를 추출해 재사용 가능한 문서 컴포넌트로 만든다.

- 표지
- 장 제목
- 절 제목
- 질문 제목
- 정량 차트와 결과표
- 정성 요약과 인용문
- 종합 해석
- 개선 제언
- 헤더·푸터

## 6. PDF·HWPX 출력 품질 기준

### PDF - 1차 승인 기준

- 원본 디자인과 같은 글꼴·굵기·밑줄·기울임·화살표 의미 체계
- 잘린 글자, 겹침, 표 넘침, 고아 제목이 없음
- 목차·장 번호·페이지 번호가 실제 페이지와 일치
- 차트 수치와 표 수치가 동일
- 바로 인쇄·제출 가능한 상태

### HWPX - 편집 원본 기준

- PDF와 동일한 장·절·질문 순서
- 제목·본문·강조·표 스타일이 의미 단위로 유지
- 표와 문단이 한글에서 직접 수정 가능
- 이미지로 통째로 붙인 본문을 사용하지 않음
- 차트는 필요 시 이미지여도 되지만 제목·주석·표는 편집 가능하게 유지
- 페이지가 일부 달라질 수 있어도 문서 구조와 스타일은 PDF와 일치

### 권장 렌더링 구조

하나의 공통 보고서 데이터 모델을 PDF와 HWPX가 각각 렌더링한다.

```text
Raw data
  -> 문항 역할·척도 매핑
  -> 공통 Report Document 모델
  -> PDF 렌더러
  -> HWPX 렌더러
```

PDF를 만든 뒤 변환해서 HWPX로 만드는 방식이나, HWPX를 이미지화해서 PDF로 만드는 방식은 피한다.

## 7. 담당자 필수 검수 항목 권장안

### A. 입력·설문 구조

- 업로드 파일과 프로젝트명이 맞는가?
- 유효 응답자 수와 제외 기준이 맞는가?
- 각 문항의 역할(만족도·중요도·NPS·주관식)이 올바르게 매핑됐는가?
- 점수 척도와 점수 방향이 맞는가?

### B. 정량 결과

- 핵심 평균·비율·NPS가 원본과 일치하는가?
- 일부 응답자만 대상으로 한 조건부 평균의 n이 명확한가?
- 표본이 작은 교차분석을 과도하게 해석하지 않았는가?
- 동점과 큰 응답 편차가 순위에서 오해되지 않는가?

### C. 정성 결과

- 인용문이 원문과 일치하는가?
- 긍정·부정·중립 분류가 문맥과 맞는가?
- 카테고리가 지나치게 합쳐지거나 쪼개지지 않았는가?
- 인사이트와 제언이 실제 응답 근거를 벗어나지 않는가?

### D. 최종 보고서

- 제품·기업·일정·담당자 정보가 맞는가?
- 목차와 포함 섹션이 프로젝트에 적합한가?
- 핵심 결과 요약이 본문 수치와 모순되지 않는가?
- 제언의 우선순위와 표현을 담당자가 승인했는가?
- PDF에서 페이지 깨짐이 없는가?
- HWPX에서 텍스트·표를 정상적으로 수정할 수 있는가?

## 8. 자동 검증과 사람 검수의 경계

| 자동으로 보장할 항목 | 사람이 승인할 항목 |
|---|---|
| 행 수, 결측, 척도 범위 | 문항 역할 매핑의 의미 적합성 |
| 평균, 표준편차, 비율, NPS 산식 | 조건부 표본 결과의 해석 적절성 |
| 표와 차트의 수치 일치 | 정성 분류와 인용문의 맥락 |
| 목차·장 번호·페이지 번호 | 종합 해석과 개선 제언 |
| PDF 오버플로·겹침 검사 | 최종 발행 승인 |

## 9. 담당자에게 제시할 결정 항목

아래에는 권장안을 미리 표시한다. 담당자는 승인하거나 수정하면 된다.

1. **시각 양식**
   - 권장: 2024 공양식을 브랜드·기본 스타일 기준으로 사용하고, 리바랩스·케어클의 최신 결과 블록을 결합
   - 대안: 리바랩스 양식을 그대로 회사 기본 양식으로 사용
   - 확인 질문: 2024 공양식이 현재도 유효한 공식 표준인지, 이후 변경된 브랜드 규칙이 있는지
2. **SW MVP 필수 목차**
   - 권장: 3절의 8개 의미 영역
3. **조건부 섹션 처리**
   - 권장: 데이터가 없으면 제외하고 목차·장 번호 자동 재생성
4. **PDF 승인 수준**
   - 권장: 바로 인쇄·제출 가능한 수준을 출시 기준으로 설정
5. **HWPX 승인 수준**
   - 권장: PDF와 구조·스타일은 같고 모든 본문·표를 한글에서 수정 가능
6. **사람 검수 범위**
   - 권장: 입력 매핑, 주요 정량 예외, 정성 분류·인용, 제언, 최종 문서
7. **실제품 개발 시점**
   - 권장: SW 골든 샘플과 신규 SW 데이터 1건 이상 통과 후 시작
8. **워드클라우드 공통 적용**
   - 권장: SW·실제품 공통 문항에 같은 블록으로 적용하되, 유효 주관식 응답과 최소 표본 기준을 충족할 때만 생성
   - 확인 질문: 최소 유효 응답 수, 제외어·유사어 통합 검수 담당자, 문항별 생성 범위
