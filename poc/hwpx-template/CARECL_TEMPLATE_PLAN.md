# 케어클 실제품 템플릿 분석 및 공통 모듈 계획

## 원본에서 확인한 실제품 전용 구조

- III. 기능별 고객 경험 평가
- IV. 고객 여정 기반 경험 평가
- V. 핵심 구매 요소
- VI. 4대 가치 만족도
- VII. NPS 지수 및 종합 만족도
- VIII. 결과 종합 및 제언

케어클 원본은 기능별·4대 가치별 분석 안에 긍정/부정/중립 의견과 인용문을 담는 서식이 있다. 다만 리바랩스처럼 기능별로 **도넛 그래프 + 긍정/부정/중립 비율표 + 세 극성 요약**이 하나의 모듈로 고정되어 있지 않다.

## 두 제품군에 공통으로 넣을 모듈

각 기능/가치의 정성 분석 시작 전 다음 순서로 삽입한다.

1. `주관식 응답 감정 분석` 제목
2. 긍정 / 부정 / 중립 도넛 그래프
3. 세 극성의 `비율(%) · 절 수` 표
4. 긍정 / 부정 / 중립 요약 1문장씩
5. 극성별 카테고리, 대표 인용문, 분석 인사이트

수치는 DB `categories[].clauseCount`의 극성별 합계로 계산하고, 분모는 세 극성 합계다. 즉 원문 문장 수가 아니라 현재 정성 파이프라인이 분류한 절(clause) 수를 명시적으로 사용한다.

## 원본 양식 보존 원칙

- 케어클의 고객 여정, 실제품 사용성/물리적 조작성, 핵심 구매요소 구조는 유지한다.
- 리바랩스의 SW 기능·중요도/만족도 종합 구조는 유지한다.
- 공통 모듈은 각 원본의 기존 표·제목·본문 글자 스타일을 복제해 추가한다. HTML로 새로 그리지 않는다.
- 인용문은 원문을 자르거나 AI가 재서술하지 않는다. 각 카테고리에는 가변 반복 블록을 사용하고, 한 페이지 글자 예산을 넘으면 다음 페이지의 같은 블록으로 이어진다.
- 글꼴, 굵게, 기울임, 밑줄, 화살표, 표 테두리·배경은 복제한 원본 XML 스타일 참조(`charPrIDRef`, `paraPrIDRef`, `borderFillIDRef`)를 유지한다.

## 다음 로컬 POC 순서

1. 리바랩스의 긍정·부정·중립 반복 블록을 빈 공양식 슬롯으로 분리한다.
2. 위 공통 모듈을 케어클 기능별 분석 앞에 삽입한 HWPX 복제본을 만든다.
3. HWPX를 한글로 열어 페이지/표/그래프를 육안 검수한 뒤 PDF를 생성한다.
4. 생성된 PDF 페이지 자체를 웹뷰로 사용한다. 웹 편집은 HWPX의 문단·표 셀·스타일 런에 매핑하여 재생성한다.
